# Workflow: issue to PR

- The spec is the issue you are working on, plus the issues it links to. Build only what the
  issue asks for.
- Where something is unclear, write down the assumption in the PR description.
- The PR description lists the tests that were added, and the commit history shows the tests
  coming before the implementation (see [testing.md](testing.md)).
- An issue marked as still being designed: leave it alone.
